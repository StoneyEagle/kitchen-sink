# Callouts

<!-- block: 01KPMM1YFGHD5MGBXDYVV0438R -->
Every callout variant, each with a title, a short body, and at least one inline mark so renderers get exercised on composition.

<!-- block: 01KPMM1YFGWVX99BSMRWH1MDDP -->
```callout:info
title: Info
body: |
```

<!-- block: 01KPMM1YFKX68TT18KZDYN1R5T -->
```callout:tip
title: Pro tip
body: |
  Use *tip* callouts sparingly. The signal collapses if every paragraph is a tip.
```

<!-- block: 01KPMM1YFMB34NBMSG5DBZ80WK -->
```callout:note
title: Author's note
body: |
  A `note` is the softest variant. It's what you reach for when there's nothing scarier than "you might not have noticed this".
```

<!-- block: 01KPMM1YFMBN5VBPGPV5ZSKC0N -->
```callout:success
title: Shipped
body: |
  `success` means a thing worked. Use it in tutorials after a step that confirms progress.
```

<!-- block: 01KPMM1YFMJKWVM5SXCEP8HVRX -->
```callout:warn
title: Heads up
body: |
  Warnings flag behaviour that's likely to surprise. Not a breakage â€” just "watch out".
```

<!-- block: 01KPMM1YFMPNX44HK0HJRKRJH9 -->
```callout:danger
title: Do not
body: |
  Danger means don't. When you see one of these, the instruction is a **hard stop** â€” there's something that will break if you ignore it.
```

<!-- block: 01KPMM1YFNNSPB8DCSNXTD6FWD -->
```callout:quote
title: From the owner
body: |
  The `quote` callout wraps a citation in the same chrome as the other variants so it visually lines up with the rest of a docs page.
```
